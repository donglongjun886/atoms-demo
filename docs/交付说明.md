## 演示环境声明

- 本项目为**演示用途**：账号密码**明文存储于浏览器 localStorage**，请勿使用真实密码；
- 数据全部存储在浏览器本地（localStorage），无服务端；登录页提供"重置 Demo 数据"一键重置；
- 请使用桌面端浏览器（窗口宽度 ≥1280px）、单标签页访问；
- 默认使用 Mock 引擎驱动 Agent 对话（确定性脚本），架构预留可插拔 LLM Provider 接口。

## 本地运行

```bash
npm install
npm run dev
```

构建与测试：`npm run build`、`npm test`。

## 后续规划

本 Demo 的架构已为此预留接口，按优先级排序：

1. **LLM Workflow 框架（最高优先级）**：Mock 引擎替换为真实多 Agent 协调层——`src/engine/` 的状态机、阶段交接与审批节点保持不变，对话脚本换成 LLM 生成；接入点即已交付的 `src/llm/provider.ts` 可插拔接口，补一个 OpenAI 兼容 Provider 与 API Key 设置界面即可切换。
2. **过程可信度增强**：Agent 消息挂工具卡片（读了什么文件、跑了什么命令），构建产出钉 Version 卡片，支持按版本回滚——对齐官方 Atoms 的 approval/version 语义。
3. **真实协同**：localStorage 换成服务端 + WebSocket，单浏览器切号升级为跨设备实时共编；邀请通知升级为服务端推送。
4. **数据洞察**：基于项目历史识别常见需求模式，输出技术栈推荐与协作效率指标（响应时间、迭代次数、一次通过率）。
